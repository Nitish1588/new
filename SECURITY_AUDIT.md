# Security Audit

Static review only. No exploit requests, production access, or destructive tests were performed. Do not copy credential values from source into tickets/docs; any credentials found in code should be treated as exposed and rotated.

| ID | Severity / confidence | Evidence and impact | Recommended remediation / tests |
| --- | --- | --- | --- |
| SEC-01 | **Critical / Confirmed by static flow** | [User controller base](../../api/ravi_bollymints-api-25c52a20b786/module/User/src/Controller/AbstractUserController.php) leaves most anonymous paths allowed. [User authentication service](../../api/ravi_bollymints-api-25c52a20b786/module/User/src/Service/UserAuthenticationService.php) `profiledit()` selects a user by body email and updates profile/password without validating current password; `createpassword()` updates by route user id. Forgot-password mail links contain a user id, not a demonstrated single-use signed token. An unauthenticated caller may be able to change another account's password/profile or reset it. No runtime exploit was attempted. | Require authenticated identity for profile changes and use session user id, never body email; require current password or verified one-time, random, expiring reset token; invalidate tokens/sessions after reset. Add unauthenticated profile/reset denial tests and cross-account IDOR tests. |
| SEC-02 | **High / Confirmed in source** | Sensitive SMTP/social integration credentials are embedded in [API auth service](../../api/ravi_bollymints-api-25c52a20b786/module/User/src/Service/UserAuthenticationService.php) and [legacy game controller](../../game/ravi_bollymints-bollymints-6a962ebafcfa/application/controllers/Welcome.php). This includes values committed with the archive. | Revoke/rotate immediately; move secrets to deployment secret storage; scan repository/history and logs; add secret scanning. Test startup with missing/invalid secrets and ensure no credential serialization. Values are intentionally omitted. |
| SEC-03 | **High / Confirmed directive; runtime scope needs verification** | [Public web API client](../../web/ravi_bollymints-web-97661d85ac77/src/definitions/apis/client.js) sets `NODE_TLS_REJECT_UNAUTHORIZED` to `0`. In Node-side Next execution this disables certificate verification for outbound TLS, permitting interception. Browser TLS behavior is separate. | Remove the override, use trusted certificates, and fail closed. Add SSR/API client test asserting TLS verification stays enabled; test invalid cert rejection in the deployed Node runtime. |
| SEC-04 | **High / Confirmed unsafe construction** | [Legacy Welcome controller](../../game/ravi_bollymints-bollymints-6a962ebafcfa/application/controllers/Welcome.php) `submitjumble()` reads `$_POST['txt_jumblemstrid']` and interpolates it into a SQL predicate. The direct query can be manipulated as SQL input. More raw SQL in the legacy controller warrants review. | Replace all interpolated input with CodeIgniter query bindings/prepared statements; validate positive integer identifiers and bind them. Add injection regression cases and ensure the query remains scoped to the session user. |
| SEC-05 | **High / Strong indication** | [Shared API model](../../api/ravi_bollymints-api-25c52a20b786/module/Application/src/Model/AbstractModel.php) `modelForGet()` encrypts answer/question/words with a fixed in-source AES key and deterministic IV derived from it. A fixed key/IV undermines confidentiality and rotation; CBC here has no authenticated integrity. | Rotate the encryption key; use managed secret storage and a vetted authenticated encryption format with random nonce/versioned ciphertext. Re-encrypt existing data under a migration plan. Add ciphertext tamper/key-rotation tests. |
| SEC-06 | **High / Strong indication** | API [Grid scorer](../../api/ravi_bollymints-api-25c52a20b786/module/Application/src/Service/Games/GridService.php) and [MatchPoint scorer](../../api/ravi_bollymints-api-25c52a20b786/module/Application/src/Service/Games/MatchPointsService.php) count client-supplied `questions[*].is_correct` values. If not independently checked elsewhere, forged payloads can award mints/rewards. | Recompute correctness from server-stored answers; ignore client score/correctness/mints. Add forged-score tests for every game type and verify balances transactionally. |
| SEC-07 | **Medium / Confirmed code structure** | [Admin controller base](../../api/ravi_bollymints-api-25c52a20b786/module/Admin/src/Controller/AbstractAdminController.php) defines a role/resource permission map and `checkPermission()`, but no call sites were found in concrete admin controllers. Admin authentication restricts role classes but may not apply per-resource CRUD permissions. | Enforce authorization through centralized middleware/policies or explicit controller checks. Add role × resource × operation tests and verify direct API calls, not only UI hiding. |
| SEC-08 | **Medium / Confirmed contract mismatch candidate** | Public `AuthApi.resetpassword` posts a bare password value, while API parsing/service reads a `password` key from decoded request data. This likely fails or returns server error; runtime response not checked. | Send a JSON object `{ "password": "..." }`, validate password policy server-side, and add request/response contract tests. |
| SEC-09 | **Medium / Needs verification** | API user controller's `submit` exception branches on a client cookie and path substring; `strpos()` truthiness and inverted cookie condition make guest submission policy difficult to reason about. `GameTypeController::submitAction()` has the explicit user-id check commented out. | Replace substring/cookie logic with explicit route metadata and a deliberate guest policy; bind score writes to a verified user or clearly separate guest results. Test missing/forged cookies and logged-in/out submits. |

## Reliability and Privacy Notes

- API game transactions update points and status through multiple table calls; transaction boundaries/idempotency were not established.
- Upload type/size checks, CSRF policy, rate limiting, CORS deployed values, password policy, reset token expiry, and log redaction need runtime/config review.
- API models remove fields for serialization, but the exact sensitive-field policy should be audited per model. Never assume hidden UI fields are protected.
- No evidence of a webhook handler or duplicate-payment idempotency key was confirmed.

## Confidence Limits

Findings are source-based, not penetration-test results. SEC-01 and SEC-04 identify direct risky paths; exploitability depends on deployed routing/configuration and any upstream controls not present in these application trees. Source credentials must be rotated regardless of whether deployment currently uses them.
